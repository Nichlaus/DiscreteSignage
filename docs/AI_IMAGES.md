# AI advert creation

## Local implementation — 25 October 2026

Owner portal form and generateAdvertImage callable implemented, not deployed.
The existing OpenAI secret binding is reused; no key was read or copied. No live
image-provider request or production configuration change in this milestone.

An owner provides an advert name, design brief (2,000 characters maximum), exact
wording (optional, 500 characters maximum) and landscape, portrait or square shape.
Only brief, wording, shape and a hashed user safety identifier reach OpenAI. No
existing media, playback URLs, email address or business records are sent.

The Images API adapter uses gpt-image-2.5-flare, medium quality, moderation:auto,
one opaque JPEG at 1536×864, 864×1536 or 1024×1024. These are not 4K outputs. The
provider timeout is 150 seconds, response JSON is capped at 12 MiB and decoded
source bytes at 8 MiB. Remote URLs are never followed. Full image decoding checks
the exact requested dimensions, strips metadata and returns a lossless WebP
preview capped at 6 MiB. Function limits: 210 seconds, 1 GiB, concurrency 1,
maximum 2 instances. The portal call timeout is 220 seconds.

Generation verifies App Check, an active verified owner, same-business membership,
active signage and aiStudio trial entitlement and a non-full library. It rechecks
access before delivering the preview. Provider failures are sanitized. Generation
does not create Storage objects, library records or screen assignments. Preview
bytes exist only in the response and current browser page; leaving/refreshing
discards them. Raw prompts and generated bytes are not logged or written to quota
records. Provider-side data handling remains subject to the OpenAI account policy.

After checking the preview, the owner explicitly chooses Add to media library.
This uses the existing media reservation, private signed upload, completion and
playback-validation endpoints. All normal tenant, entitlement, 100-file/1-GiB
library and immutable-generation checks still apply. Playback is never assigned
automatically. Source provenance is not a security claim: saved images currently
appear as ordinary library uploads. Server-generated provenance tagging is future
work.

The browser retains one upload request ID/media ID for save retries and checks the
library status before re-uploading. A lost validation response can be recovered
without a second reservation or upload. Failed saves may leave normal private media
entries consuming allowance; eligible expired/rejected uploads use the existing
eight-day cleanup flow. Discarding a preview does not delete an already-started
library save. No persistent unsaved-generation archive or regeneration retry exists.

## Usage and activation

Image usage is separate from playlist drafting. Server-only
platformConfig/imageGeneration.enabled defaults off. Fixed limits: 3 requests per
business per UTC day, 10 per business trial total and 100 platform-wide per UTC day.
One request per business can run at a time; a 240-second lease recovers crashes and
a 30-second minimum spacing discourages duplicate clicks. All reservations count,
including provider failures and discarded previews. No automatic paid API retry.

Counters are platformUsage/imageGeneration and
businesses/{businessId}/imageGenerationUsage/current. Client reads/writes are denied.
These are request limits, not a monetary cap or token-cost ledger. Never clear the
total to extend a trial. The enablement switch prevents new reservations; it does
not cancel in-flight generation or remove already-delivered previews.

Before deployment, confirm image-model access and any required organization
verification on the existing OpenAI project. Deploy only the new callable and
Hosting, verify secret binding and unauthenticated denial, then enable the image
switch. Run a bounded real generation, inspect wording/price accuracy, explicitly
save to the library, verify ready status and test on a temporary display. The
feature should remain off until that activation is requested and checked.

## Evidence and limitations

Automated checks cover authorization, cross-business denial, entitlement, revoked
access during generation, full decode, unsafe provider responses, independent image
quotas and save retry behavior. Local browser testing uses a labelled synthetic
fixture, not AI artwork. Real model quality, latency and account availability are
unverified. AI can invent or misspell wording despite prompt instructions; human
review is required, and there is no automated OCR correctness guarantee.

Validation result: 166 tests passed against isolated demo emulators; production
build passed. Local browser verified preview, disabled save until review, explicit
save success and preview removal. Preview evidence: artifacts/image-creation-preview.png.

API reference: [OpenAI image generation](https://developers.openai.com/api/reference/resources/images/methods/generate).
